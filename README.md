# Somnium — Сны и Рассудок

Мод для Fabric (Minecraft 26.1), реализующий:
- 100%-й переход в один из **7 уникальных снов** при засыпании в кровати
- Систему **Рассудка**, падающего после суток без сна
- **Прорыв кошмаров в реальность** при низком рассудке (Bleed-Through)

## ⚠️ Честно о статусе этого каркаса

Я сгенерировал полную структуру проекта и рабочую логику всех систем, но **не компилировал
и не запускал** этот код: в моей рабочей среде нет доступа к репозиториям Fabric/Mojang
(`maven.fabricmc.net`, серверам с самими jar-файлами Minecraft), поэтому Gradle-сборку нужно
проверить у себя. Версия 26.1 очень свежая (вышла в марте 2026, первая без обфускации), часть
конкретных имён классов/событий Fabric API могла отличаться от того, что я использовал.

1. **7 JSON-измерений созданы** (`data/somnium/dimension/*.json` + общий `dream_dimension_type.json`).
   Генераторы внутри — **плейсхолдеры** (`minecraft:flat`), чтобы измерения физически существовали
   и были проходимыми уже сейчас. Настоящая генерация локаций — Приоритет 2.
2. **Спавн монстров при входе в сон реализован** (`DreamManager.spawnDreamMonsters`) — при засыпании
   вокруг игрока реально появляются монстры из `dream.monsterEntityIds()`.
3. **Точка спавна в сне** учитывает heightmap и подстрахована от падения в пустоту (актуально для

## ⚠️ Обновление: Приоритет 1 был закрыт преждевременно — теперь исправлено по-настоящему

Предыдущая итерация писала, что «Приоритет 1 закрыт», но не была протестирована и содержала
баги, из-за которых на практике игрок падал насмерть сразу при входе в сон и не видел ни
мобов, ни предметов мода. Разобрано и исправлено:

1. **Падение насмерть при входе в сон.** `DreamManager.findDreamSpawn` брал Y через
   `world.getTopY(...)`, который для чанка (0,0) измерения сна — при самом первом визите
   игрока туда — мог не успеть досчитать хайтмап к моменту вызова. Игрок спавнился высоко в
   воздухе, разбивался о плейсхолдер-платформу, `ServerPlayerEntityMixin` ловил "смерть" и тут
   же будил игрока обратно — выглядело это как "спавнит сверху -> мгновенно назад в мир".
   Исправлено: точка спавна теперь считается арифметически (`ModDimensions#platformSurfaceY`)
   из известных высот слоёв плейсхолдер-генератора, без зависимости от готовности чанка. Плюс
   добавлена страховка: сброс `fallDistance`/скорости и короткое окно неуязвимости (1 секунда)
   сразу после любой телепортации в сон/из сна.
2. **Монстры "не спавнились".** Это было прямым следствием бага №1 — сон завершался (смертью
   и возвратом) быстрее, чем игрок успевал увидеть заспавненных монстров. Отдельно найден и
   исправлен настоящий баг: `Registries.ENTITY_TYPE.get(id)` — это `DefaultedRegistry` с
   дефолтом `minecraft:pig`, поэтому `.get()` на незарегистрированный id никогда не возвращал
   `null` и предупреждение в лог не срабатывало. Заменено на `.getOrEmpty(id)`. Заодно найдена
   и убрана мёртвая ссылка на `phantom_eel` в сне "Тонущий город" — такая сущность никогда не
   регистрировалась в `ModEntities`.
3. **"Нет предметов мода."** `ModItems` регистрировал `clarity_shard` и `dream_catcher` в
   `Registries.ITEM`, но их никто не добавлял ни в одну вкладку творческого режима — при этом
   перевод `itemGroup.somnium` в lang-файлах уже был заготовлен, просто не было ни класса
   вкладки, ни вызова регистрации. Добавлен `ModItemGroups` + вызов `register()` из
   `SomniumMod#onInitialize`. **Важно:** моделей/текстур для предметов по-прежнему нет (это
   отдельная задача Приоритета 3) — предметы теперь видны во вкладке, но будут отображаться
   текстурой-плейсхолдером (бело-чёрная "шашечка"), пока не добавлены реальные ассеты.

Как и раньше: я не компилировал и не запускал этот код (нет доступа к Fabric/Mojang maven в
моей рабочей среде) — при первой сборке эти изменения тоже стоит проверить по логам.

## ⚠️ Обновление: закрыт ваш список из 3 пунктов (HUD цели / вещи / скип ночи)

Это не пункт из Roadmap ниже — это отдельный список проблем, который вы описали в чате.
Разобрано и исправлено:

1. **"Задание сна непонятно, быстро пропадает."** Причина: цель сна отправлялась только через
   ванильный `TitleS2CPacket`/`SubtitleS2CPacket` (`DreamManager#sendDreamTitle`) с жёстко
   заданным временем жизни — 10 тиков появление + 60 тиков показ + 20 тиков исчезание = 90 тиков
   (~4.5 секунды), после чего текст пропадал навсегда, даже если игрок не успел прочитать.
   Добавлен новый пакет `DreamHudPayload` и постоянный HUD-виджет `DreamObjectiveHudRenderer`
   (клиент, вверху экрана): название сна + текст цели + полоса оставшегося до пробуждения времени,
   стилизованная под шкалы статов "как у Ведьмака" — бронзовая двойная окантовка, градиентная
   заливка, цвет плавно уходит от фиолетового (много времени) к тревожному красному (мало времени).
   Висит на экране всё время, пока сон активен, и обновляется раз в секунду
   (`DreamManager#sendHudUpdateIfDreaming`, вызывается из `SomniumMod` рядом с тиком рассудка).
   Старый тайтл оставлен только как короткая атмосферная надпись названия сна при входе, дублировать
   цель им больше не нужно.
2. **"Попадаю в сон с вещами из реального мира."** `DreamManager#enterDream` теперь снимает копию
   всего инвентаря игрока (`snapshotAndClearInventory` — основной инвентарь + броня + офф-хенд,
   всё, что покрывает `PlayerInventory#size()`) и полностью очищает реальный инвентарь ПЕРЕД
   телепортацией в сон. Снимок хранится в памяти прямо в `ActiveDream` (без сериализации в NBT —
   он нужен только внутри одной серверной сессии, точно так же, как уже хранится точка возврата).
   При любом варианте пробуждения — по таймауту, вручную, или через смерть во сне
   (`onDeathInDream`, который тоже вызывает `wake()`) — `DreamManager#wake` вызывает
   `restoreInventory` и **целиком** заменяет инвентарь на тот снимок: всё, что игрок подобрал или
   потерял во сне, в явь не переносится.
3. **"После пробуждения не скипается ночь."** Причина тоньше: ванильный скип ночи требует, чтобы
   игрок непрерывно оставался `isSleeping()==true` в одном и том же мире, пока сервер несколько
   тиков подряд не убедится, что спит достаточный процент игроков — только тогда он сам домотает
   время до утра. Наш код обрывает это на середине: `enterDream` сам вызывает `player.wakeUp()` и
   тут же телепортирует игрока в измерение сна, то есть игрок формально "передумал спать" с точки
   зрения ванильной логики, и реальный мир просто продолжает идти в обычном темпе (не домотанным)
   всё время, пока игрок отсутствует (иногда несколько игровых часов). В результате игрок мог
   "проспать" весь сон и вернуться — а на улице всё ещё ночь. Исправлено вручную: `wake()` теперь
   вызывает `forceMorningIfNight(returnWorld)` — если в мире возврата сейчас ночь, время
   домёвается до утра и гасится дождь/гроза, как это в норме делает обычная кровать.

Попутно, при работе над пунктом 3, нашёл и исправил соседний баг, который иначе выстрелил бы при
первом же тестировании: `tickActiveDreams` раньше проходил по карте активных снов через
`ACTIVE.forEach(...)`, а `wake()` внутри этого же прохода удаляет запись из той же карты — то есть
сервер падал с `ConcurrentModificationException` при **любом** естественном завершении сна по
таймауту. Теперь итерация идёт по снимку ключей (`new ArrayList<>(ACTIVE.keySet())`).

Как и раньше: не компилировал и не запускал эти изменения (нет доступа к Fabric/Mojang maven).
Особенно стоит проверить у себя при первой сборке:
- Сигнатуры `DrawContext#fillGradient` и `DrawContext#drawCenteredTextWithShadow` в HUD-рендерере —
  если в 1.21.11 их аргументы отличаются, поправьте по автодополнению IDE.
- Точный диапазон "это ночь" в `forceMorningIfNight` (сейчас грубо `dayTime >= 12000`) — если
  хотите 1-в-1 совпадение с порогом, с которого вообще можно лечь в кровать, сверьте с decompile.
- `PlayerInventory#size()`/`getStack`/`setStack`/`clear()` — использованы по общей для 1.21.x API,
  но если в 26.1/1.21.11 инвентарь перегруппировали иначе, поправьте `snapshotAndClearInventory`.

## ⚠️ Обновление: краш в "Тонущем городе" + мобы были невидимы (не отсутствовали)

Ответ на присланный вами crash-report (`NullPointerException ... EntityRenderDispatcher`,
`Level dimension: somnium:dream_drowning_city`) и жалобу "дверь выхода есть, а сущностей и
новых предметов нет". Разобрано и исправлено:

1. **Причина краша.** `ModEntities.PHANTOM_EEL` давно зарегистрирован на сервере и участвует
   в "Тонущем городе" (см. `DreamRegistry`), но в клиентском модуле (`SomniumClient.java`) для
   него не было строчки `EntityRendererFactories.register(...)` — той же самой регистрации,
   которая уже была сделана для остальных 9 сущностей. Это ровно тот класс бага, который уже
   один раз чинили для всех монстров разом, просто забыли добавить его для 10-го, добавленного
   позже. Без зарегистрированного рендерера клиент падает с NPE в момент, когда сущность впервые
   попадает в область отрисовки — то есть почти сразу после входа в сон "Тонущий город", отсюда
   и ощущение "мобов вообще нет": игра крашится раньше, чем вы успеваете их увидеть. Добавлена
   недостающая строка регистрации.
2. **"Сущностей не видно" — это была ОТДЕЛЬНАЯ проблема, не только краш.** Даже без учёта краша,
   `NightmarePlaceholderRenderer` (заглушка, добавленная в прошлой итерации именно для того, чтобы
   убрать этот же NPE) была написана так, что **ничего не рисовала** — `createRenderState()`
   возвращал пустое состояние без модели/текстуры. Она честно решала задачу "не крашиться", но
   ценой того, что все 10 монстров-кошмаров были буквально невидимы (при этом реально существовали,
   спавнились, дрались и роняли `NIGHTMARE_ESSENCE` — это можно было проверить по логам сервера
   и по факту получения урона, не видя самих мобов). Переписано: рендерер теперь использует ванильную бипед-модель зомби
   (`EntityModelLayers.ZOMBIE`) и подставляет разную ванильную текстуру под каждый вид кошмара
   (drowned → Утопленник-переродок, husk → Кричащий Шахтёр, zombie_villager → Одичавший Житель
   и т.д. — см. `NightmarePlaceholderRenderer#textureFor`), чтобы монстры были видны и хоть

## Частая ошибка: "Minecraft 26.1 requires Java 25 but Gradle is using X"

Значит, в системе Gradle нашёл не ту версию Java (например, 17 или 21 вместо 25).
Исправление:
1. Установите **Eclipse Temurin JDK 25** (не JRE) — https://adoptium.net/temurin/releases/?os=windows
2. Найдите папку установки, обычно `C:\Program Files\Eclipse Adoptium\jdk-25.x.x-hotspot`
3. Откройте `gradle.properties` в проекте, раскомментируйте и заполните строку:
   ```
   org.gradle.java.home=C:\\Program Files\\Eclipse Adoptium\\jdk-25.0.3-hotspot
   ```
   (двойные `\\`, точное имя папки посмотрите у себя — версия может отличаться)
4. Запустите `gradlew.bat build` заново

## Сборка (Windows)

Отдельно устанавливать Gradle **не нужно** — в проекте уже есть настоящий Gradle Wrapper
(`gradlew.bat`, файлы взяты из официального шаблона `FabricMC/fabric-example-mod`).
Нужна только установленная **Java 25** (JDK, не просто JRE) — проверить: `java -version`
в командной строке.

1. Распакуйте архив
2. Откройте `cmd`/PowerShell в папке `somnium-mod`
3. Выполните:
```
gradlew.bat build
```

При первом запуске wrapper сам скачает Gradle 9.5.1, затем Gradle скачает Minecraft 26.1,
Fabric Loader и Fabric API — нужен нормальный интернет, первый запуск может занять несколько минут.

Готовый мод появится в `build\libs\somnium-0.1.0-alpha.jar` — кладёте в папку `mods`
вашего Fabric-клиента/сервера 26.1.

Если увидите ошибку в консоли — просто пришлите мне её текст, я поправлю код.
